# Organisation recipient contract for the combined funding-flows release

The served object is exactly `{id, display_name, ror, country_code, roles, share, basis, asserted_by}`. This release intentionally uses the flat matched identity rather than C-schema-gap §1's nested institution/type proposal. A match uses the institution's canonical display_name; an unmatched organisation keeps the source name, with null id/ror. The original source name, source ROR, source field, feed and award key remain in award_recipients_raw and recipient_org_selected/recipients_resolved, and matching evidence joins those records to the served award. They are not additional public fields in this release. A separate served source_name and organisation type would be a subsequent schema decision; no implicit type is inferred here.

`share` is the explicitly reported allocation, or null. Null means unknown, not zero or an equal share. Organisation roles are overlapping assertions: one organisation can be both partner and implementing on the same award. Never sum award amounts or shares across roles as if they were disjoint monetary recipients. Role 2 is accountable/oversight, mapped to partner, and role 4 is implementing. Role 2 does not assert receipt of money. The served `roles` array is sorted and deduplicated, for example `["implementing", "partner"]`. One object represents an organisation with compatible share and attribution assertions. Same matched institution with different matching methods collapses to the strongest evidence: `ror`, then `affiliation_matcher`, then `institution_name`. Unmatched identity includes the exact source name and country, so same-name organisations in different countries stay separate. Conflicting shares or source attribution are preserved as distinct assertions, never summed or silently chosen; countries/regions follow their separate allocation policy.

`basis` identifies the identity match (ror, affiliation_matcher, institution_name), falling back to the source basis when unmatched. `asserted_by` identifies who asserted the participation. An OpenAlex match does not change the source's role assertion. country_code is organisation country (source first, matched institution fallback), never place of performance.

`institution_awarded` retains its existing SQL derivation, with the explicitly declared 47 FCDO country-guard changes in `EXPECTED-NON-AFRICA-FIELD-CHANGES.md` and is not guaranteed to be the complete matched subset of recipients. The new matching stage does not supply its inputs or research_scope inputs. Display recipients are capped at 100; recipients_full remains uncapped for deterministic hashing/indexing.

The producer continues to store scalar `role` per source assertion for audit and loss checks. Only the served API objects use `roles[]`; source-row counts do not shrink when roles are combined. This pre-publication contract supersedes the FIX2 scalar-role contract.
